# Настройка проекта с нуля

Как развернуть reverse_bot на чистой машине после `git clone`. Подробности по
каждому шагу — в [README.md](README.md); здесь только порядок действий.

## 0. Что нужно заранее

- **Docker Desktop** (запущенный) — в нём собирается образ песочницы.
- **Python 3.10+** — хостовая часть (оркестратор, судья).
- **Windows** — команды ниже для PowerShell; на Linux/macOS замените `.ps1`/`.cmd`
  на прямые вызовы `docker`/`python`.

## 1. Хостовые зависимости

```powershell
pip install -r requirements.txt
```

Ставит `litellm` (доступ к моделям), `python-dotenv`, `paramiko` (SSH к Pi),
`PyYAML`. RE-инструменты (Ghidra, radare2, …) сюда НЕ входят — они живут в
контейнере.

## 2. Образ песочницы

```powershell
.\build.ps1
```

Первая сборка 15–30 минут (Ghidra ~400 МБ). В конце прогонится самопроверка —
она печатает, что установилось. Критичен только JDK; часть инструментов помечена
необязательными. Для Pi OS 2023–2024: `.\build.ps1 -Suite bookworm`.

## 3. Ключи и доступы — `.env`

```powershell
copy examples\.env.example .env
```

Открой `.env` и впиши **хотя бы один** ключ модели:

- `OPENROUTER_API_KEY` — один ключ на все модели (проще всего), либо
- прямые ключи провайдеров (`ANTHROPIC_API_KEY`, и т. д.).

Точные id моделей — на [openrouter.ai/models](https://openrouter.ai/models).
Это **API-доступ**, не подписка ChatGPT/Claude — оплачивается отдельно, по токенам.

Настоящая Raspberry Pi необязательна. Если есть — заполни блок `RE_PI_*` и проверь:

```powershell
python agent.py --check-pi
```

## 4. Данные — вручную, их нет в git

Два каталога намеренно исключены из репозитория (`samples/`, `truth/` в
`.gitignore`): там анализируемый бинарь, защищаемый исходник и эталонные ответы.
Создай и заполни их:

```
samples/                 # анализируемое (не в git)
├── <бинарь>             #   образец для атаки
└── <зависимости>        #   .so, данные, входные файлы, нужные ему для запуска

truth/                   # эталон — виден только судье (не в git)
├── src/…                #   защищаемый код с маркерами @re-target-*
└── Cargo.toml           #   (если Rust) — имя/версия бинаря
```

Разметь защищаемое в исходниках маркерами `@re-target-const` / `-algo` /
`-defense` (см. README → раздел про разметку), затем собери цели:

```powershell
python targets_gen.py --source truth --out truth/protected.yaml --cargo truth/Cargo.toml --check
```

`--check` показывает, что распозналось, без записи. Убедился — убери `--check`.

> **Граница доверия.** `truth/` виден только судье и никогда не попадает в
> песочницу к атакующим. Не клади исходник или `protected.yaml` внутрь `runs/` —
> оттуда он смонтировался бы в контейнер. `judge.py` это проверяет и откажет.

## 5. Проверка стенда (без трат на модели)

```powershell
python tests\smoke_sandbox.py
```

Гоняет контейнер вхолостую: PATH, монтирование, отсутствие сети, эмуляция ARM.
Ключей API не требует.

## 6. Запуск RE-сессии

Аргументы атаки — в `RE_args.txt` (бинарь, зависимости, модели, бюджет, версия).
Правь этот файл, не команду. Затем:

```powershell
python run_RE.py
```

Прогонит всю цепочку: цели → атака ансамблем → оценка судьёй. Результат —
`runs/<прогон>/resilience.json` (балл стойкости и вердикт по каждой цели).

Отдельные шаги (`targets_gen.py`, `orchestrate.py`, `judge.py`) можно запускать и
вручную — см. README.

## Частые ошибки

- **`Docker недоступен`** — не запущен Docker Desktop.
- **`не задан ключ для <модель>`** — пустой `.env` или не тот ключ под id модели.
- **`нет файла целей`** — не запускал шаг 4 (`targets_gen.py`).
- **`провайдер не знает модели`** — устаревший id; сверь с openrouter.ai/models.
- **`ОТКАЗ: … внутри runs/`** — эталон положен в `runs/`; перенеси в `truth/`.
